# 快手弹幕协议笔记（2026-11-18 摸底）

目标是给 PS5 直播桥加快手弹幕，和抖音、斗鱼一样免登录收。
下面是把快手网页版前端包扒下来之后确认到的东西，**还没打通**。

## 已确认：接口

请求要带这几样，缺了会拿到网页而不是 JSON：

```
Cookie: did=web_<16 位随机>
kpf: PC_WEB
Referer: https://live.kuaishou.com/
```

| 用途 | 接口 | 说明 |
|---|---|---|
| 列表 | `GET /live_api/liveroom/recommend` | 返回 `data.list[]`，每项 `id` 是 liveStreamId，`author.id` 是 principalId |
| 详情 | `GET /live_api/liveroom/livedetail?principalId=` | 有 `liveStream.playUrls`、caption 等 |
| 长连信息 | `GET /live_api/liveroom/websocketinfo?liveStreamId=` | 正常应返回 wss 地址和 token |

`websocketinfo` 返回 `{"data":{"result":2}}` 时表示拿不到，实测推荐列表里的房间**全部是下线状态**
（`living: false`），所以一直拿到 2。要先有一个正在播的房间才能往下走。

## 已确认：protobuf 字段表

快手把 protobuf 定义直接内嵌在前端包里（36 个消息类型），这部分是硬事实，
不用猜，也不用抄别人的代码：

```
CSWebEnterRoom   token=1  liveStreamId=2  reconnectCount=3  lastErrorCode=4
                 expTag=5  attach=6  pageId=7
SCWebEnterRoomAck  minReconnectMs=1  maxReconnectMs=2  heartbeatIntervalMs=3
SCWebFeedPush     displayWatchingCount=1  displayLikeCount=2  pendingLikeCount=3
                  pushInterval=4  commentFeeds=5(重复)  commentCursor=6
                  comboCommentFeed=7  likeFeeds=8  giftFeeds=9  giftCursor=10
                  systemNoticeFeeds=11  shareFeeds=12
WebCommentFeed    id=1  user=2  content=3  deviceHash=4  sortRank=5
                  color=6  showType=7  senderState=8  time=9
SimpleUserInfo    principalId=1  userName=2  headUrl=3  mystery=4  desc=5
WebGiftFeed       id=1  user=2  time=3  giftId=4  sortRank=5  mergeKey=6
                  batchSize=7  comboCount=8  rank=9  ...
```

也就是说：**弹幕在 `SCWebFeedPush.commentFeeds`，昵称在 `WebCommentFeed.user.userName`，
礼物在 `SCWebFeedPush.giftFeeds`**。这层已经清楚了。

## 还没确认：帧格式

前端把连接代码拆到了房间页的懒加载 chunk 里，那四个首屏脚本里只有
`new WebSocket` 和 `binaryType="arraybuffer"`，没有解包逻辑。所以下面这些还不知道：

- 一帧的头部几个字节、长度怎么表示
- payload 是不是 gzip（vendors 包里带了 pako，但没找到调用点）
- 发送 CSWebEnterRoom 时是裸 protobuf 还是带壳
- 心跳间隔（SCWebEnterRoomAck 里给了 `heartbeatIntervalMs`，要连上才知道值）
- 是否需要先「注册 did」再请求 websocketinfo
