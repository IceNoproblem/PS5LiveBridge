### v5.0 修掉的 6 个历史遗留 bug

这些在 v4.8 就存在，不是 v5.0 引入的：

1. **`relay.py` 调 `Thread.cancel()`** —— `_watch` 是 `threading.Thread`，没有该方法。第一次开播正常，**停播后再开播必炸**。
2. **`cleanup()` 清空顺序错** —— 先清 `live["bili"]` 再去取 `channel`，关播永远用错通道（→「其他设备正在播放」的成因之一）。
3. **`publisher()` 用 `frame > 0` 判推流** —— `-c copy` 不解码，frame 恒为 0，**永远认为没推流**，不自动开播。改用 `out_time_ms` 递增。
4. **开播/人脸循环无异常保护** —— 网络抖动抛异常，独立线程静默死亡，状态永远卡在「正在开播」/`face_verify`。
5. **测试弹幕发太早** —— B 站开播确认比 PS5 连 IRC 早约 2 秒，消息因「无活跃连接」被丢弃。
6. **容器内 `netutil.default_gateway()` 返回空** —— 用 `netstat -rn`，slim 镜像没这命令。改读 `/proc/net/route`。

### v5.0 的核心架构结论

> **收流端必须是多连接 RTMP 服务器，不能用 `ffmpeg -listen 1`。**

- `-listen 1` 只接受 1 个连接，PS5 占住 1935 后 relay 拉不到流；
- 若用 `set_destination` 重启 ffmpeg 加转发目标，PS5 会被踢掉且**不会自动重连**（实测 3 秒后判停播）；
- **PSLinkB 的印证**：它用 Rust `rtmp-rs` 自建服务器，`max_connections(100)` —— 同样是「多连接服务器 + ffmpeg 拉流转推」；
- **最终方案**：`nginx-rtmp`（镜像自带 1.22.1 + libnginx-mod-rtmp），relay 二次拉流。

### v5.0 的 12 个模块

`statemachine`（状态校验）· `eventbus`（旁路广播）· `config_store`（运行时数据）· `ffmpeg_mgr`（二进制定位）· `danmaku_throttle`（弹幕限速）· `danmaku_history`（弹幕落盘）· `netwatch`（IP 变化）· `shutdown`（统一退出）· `twitch_title`（标题同步）· `router_api`（路由器一键配置）· `https_relay`（DNS 模式 443 中继）· `errors`（结构化错误）

### 性能实测（1080p60 / 6.1 Mbps）

| 组件 | CPU |
|---|---|
| ffmpeg relay（copy + FLV 封装 + 推 B 站） | 2.3% |
| nginx-rtmp（收流） | ~1.5% |
| Python（Flask + 监控 + 弹幕） | ~1.7% |
| **合计** | **5.5%**，内存 67 MB |

码率 入 6.13 / 出 6.10 Mbps，丢帧 0。**画质与 PSLinkB 完全一致**（两边都 `-c copy`，字节级透传）。

实际踩到的比计划多得多：

- **内置 DNS 那条路的 443 中继**：`join(timeout=30)` 会掐断 Twitch 长连接（报「无法直播」）；读 ClientHello 只 `recv(4096)` 一次，分段发送就解析不出 SNI，然后默认猜 `api.twitch.tv`，猜错报 `SSL_ERROR_SYSCALL`
- **`api.twitch.tv` 必须一起劫持**：只劫推流域名的话，PS5 拿公网 IP 直连被墙，Twitch 打不开
- **hosts 不支持通配符**：写 `live-video.net` 不会匹配 `hkg06.contribute.live-video.net`，而 PS5 连的是具体地区节点 —— 现在展开成 20 条
- **B 站域名绝不能进 hosts**：本机 ffmpeg 解析到自己 → 推流给自己 → `I/O error`
- **`config.json` 的并集逻辑只补不删**：默认值改了，老配置里的残留还在（B 站域名就是这么冒出来的）
- **界面三选一重构后再审查**：又发现 3 个 P0（`pick` 的 TDZ、结果写进 `display:none`、关闭按钮 id 悬空）和 9 个 P1

## v5.1.1beta（2026-11-01）

排查两个用户故障后集中修的一版。桌面版按 5.1.1 验收过，容器版补齐差异后定名 5.1.1beta。

- **端口检测改用 IP Helper API**（`GetExtendedTcpTable`）。原来解析 `netstat` 输出，在有安全软件的机器上整行被过滤，
  导致 5000/1935/6667 全报「没监听」，把人带偏
- **`ps5_seen` 改判据**：原来只在方案二（内置 DNS）下计算，方案三永远 false；现在方案三看 1935/6667 的劫持记录
- **`ps5.uptime` 单位修正**：nginx stat 给的是毫秒，之前直接当秒显示（59 秒显示成 58888）
- **`relay.running` 统一语义**：原来是 nginx.forwarding，与 ffmpeg 无关；现在等于 encoder
- **rtmf 的 stderr 落盘**（`logs/rtmf-stderr.log`），divert 详细日志（`logs/divert.log`），诊断包一并带上
- **启动只开默认浏览器**，删掉 Edge `--app` 独立窗口（管理员/杀软环境下会秒退，拖垮整个程序）
- **启动默认落在自检页**，新增运行环境判定（家用路由器/热点/校园网）、管理员权限、收流进程、编码进程、安全软件检测
- **更新器改目录切换**：解压到同级 `.next` → 两次 `move` 完成换版，失败自动回滚。不再用
  `powershell -ExecutionPolicy Bypass` 逐文件覆盖（杀软最敏感的特征，也是更新失败的根源）
- **前端改 SSE 长连接**，消除每 1.5 秒一条的 TCP（一台机器能攒几百条 TIME_WAIT）
- 第 3 步加速器提示改为「建议 UU」，附折叠说明（迅游用 NDIS 驱动抓不到包；UU 的 Wintun 可以）
- PS5 四项参数标注与 PS5 界面一致的字段名
- 删除已无用的 `core/rtmpserver.py`
- **新增 `core/routermatch.py`**：访问网关后台取标题，识别路由器型号与 hosts 能力，直接告诉用户方案一走不走得通
- **自检结论按所选方案分别判定**，不再一句「看起来正常」包打天下
- **容器版差异适配**：
  - 端口占用者改用 `/proc/net/tcp` 反查（精简镜像里没有 lsof，容器里 1935 一直显示「未识别到」）
  - 管理员权限走 `netutil.is_admin()`（原来是 `ctypes.windll`，容器里必抛异常 → 自检页常年一条红字）
  - 安全软件检测、防火墙规则、管理员提示在容器里不显示（不是 Windows，压根没这些东西）
  - 自检页按 `caps()` 分组：容器只显示通用项 + 方案一，方案二/三整组不渲染
  - 收流失败文案不再建议「换成 rtmf」（容器里没有 rtmf 二进制）
  - 方案一走不通时，容器版建议改路由器 DNS 静态解析，而不是把人推向容器做不了的方案二/三

## v5.1.2（2026-11-01）

5.1.1beta 的正式版。功能上砍掉一块，修掉三个用户实际遇到的故障。

- **移除画面叠加和本地画面预览**。叠加走的是转码路径，硬件编码器本来就在崩溃边缘，
  两条硬件编码同时开是 5.1.0 那批 0xC0000005 的根源。需要在画面上打字的场景交给上游：
  OBS 文本源或 B 站直播姬文本挂件，都比在桥里做更稳、更清楚
- **本地取流改给 HTTP-FLV**（`http://127.0.0.1:8098/live/stream.flv`）。原来给 `rtmp://…`，
  但 rtmf 只收不播，OBS 拉过去报 `Already publishing`
- **推流途中点「推 B 站」立刻生效**：补了输出切换的接管，点开 3 秒内进 live，不用重开程序
- **8098 绑 `0.0.0.0`**：原来只绑 127.0.0.1，局域网另一台机器拉不到
- 去掉叠加后 rtmf 与 nginx 两种收流的开销差距只剩内存占用，CPU 基本持平
